# SCP 使用手册

[English guide](../English/UserGuide.md) · [项目概览](README中文.md) · [测试与复现](测试说明.md)

scp 是 一个可靠流传输层，提供序号、确认、重传、窗口、乱序重组、拥塞控制等功能。
 它不关心底层链路，也不关心上层协议，只负责可靠传输。

## 时钟

实现按 tick 单调推进的 `uint32_t` 时钟。`SCP_TICK_SCALE` 表示每毫秒的 tick 数：核心与真实 UDP 默认 `1U`，即 1 ms；虚拟测试默认 `1000U`，即 1 μs。CMake 的 `SCP_TEST_TICK_SCALE` 只选择虚拟目标刻度。所有编译单元必须一致；核心用序号比较处理无符号回绕，连接期间不要重置时钟。

```c
extern uint32_t scp_now_time(void);
```

物理超时常数随刻度换算。初始 RTO 为 1000 ms；得到 RTT 样本后，现有估计器使用 200–2000 ms 边界。这与尚无 SRTT 时 pacing 的 1 ms 回退值是两回事。`scp_prob_configure()` 仍使用物理毫秒。

## Pacing 策略

拥塞窗口和接收窗口允许的数据按 `gap = payload_bytes * RTT / (gain * cwnd)` 分配预约时刻。每批从 `max(next_slot, now)` 开始，先给包分配当前槽，再按该包间隔推进 next-slot。发送队列为空时也保留尾槽，让下一批继续遵守前一个包的 pacing 间隔。

AIMD 使用固定阶段系数：SS 为 `2 ln 2` 对应的 Q16 值 `90852`，CA 为 `3 ln 3 / 2` 对应的 Q16 值 `107998`。PROB 全程使用 CA 系数；CA 的实际值为 `107998 / 65536 = 1.647918701171875`。每种控制器通过各自注册的回调提供 gain。尚无 RTT 样本时使用 1 ms 回退值，应用仍需周期性处理定时器。

[论文](../../Pacing_and_Congestion_Window_Growth.pdf)依次解释连续模型、离散包时序和三明治推导。[中文测试指南](测试说明.md#模型与实际执行)区分 Python 模型、实际 SCP 核心的虚拟网络实验和真实 UDP 测量。

## API

### 初始化

```c
int scp_init(size_t max_streams);
```

初始化 SCP，全局只有一份。

### 分配流

```c
struct scp_stream *scp_stream_alloc(struct scp_transport_class *st_class,
                                    int src_fd,
                                    int dst_fd);
```

创建一个流，绑定底层传输类。

**注意**

`src_fd` 是唯一的本地协议标识，`dst_fd` 指向对端对应的流，都不是操作系统 socket 句柄。流可能使用传输对象及其用户上下文期间，这些对象必须有效。启动主动连接前，先分配被动端的流。

### 选择控制器

```c
int scp_set_cc(int fd, enum scp_cc_id cc_id);
int scp_prob_configure(struct scp_stream *ss,
                       uint32_t rtt_span_ms, uint32_t loss_q16);
```

连接前、流仍为 `SCP_CLOSED` 时选择 `SCP_CC_AIMD` 或 `SCP_CC_PROB`。当前分配默认使用 PROB；测试运行器会明确选择。连接建立后切换会被拒绝。PROB 配置接受正的毫秒 RTT 跨度与 0–65536 的 Q16 丢包比例；这不会设置网络丢包率。

### 释放流

```c
int scp_stream_free(struct scp_stream *ss);
```

立即释放流、定时器及缓冲区，不执行优雅关闭。协议正常关闭或超时也可能自动释放流；不要继续使用旧指针或重复释放。

### 连接

```c
int scp_connect(int fd);
```

这个函数会与远程scp协议进行握手。

### 输入数据

```c
int scp_input(void *ctx, void *buf, size_t len);
```

输入一整个 SCP 包，SCP 会自动处理序号、确认、重传等逻辑。

### 发送数据

```c
int scp_send(int fd, void *buf, size_t len);
```

建立连接后将输入复制入队。返回 `0` 表示全部输入被接受，不是字节数，也不表示对端已收到。`SCP_ERR_NOBUF` (-2) 表示应保留应用数据，待协议取得进展后重试；`SCP_ERR_NOMEM` (-3) 不会只入队一部分输入；`SCP_ERR_GENERIC` (-1) 表示输入或状态无效。公共测试负载把应用发送积压限制在约 1 MiB，与 cwnd 分开。

### 接收数据

```c
int scp_recv(int fd, void *buf, size_t len);
```

返回复制的字节数；零表示本次没有复制数据，不能单独当作 EOF；负值表示流不存在或无效。及时消费数据，以重新开放通告接收窗口。

### 关闭流

```c
void scp_close(int fd);
```

请求排空队列后关闭，并拒绝后续新发送。关闭是异步的，期间继续处理输入和定时器。

```c
int scp_is_closed(int fd);
```

流不存在和刚分配、尚未连接时也返回真。用它判断完成前，应先记录连接是否已经开始。

### 定时器处理

```c
void scp_timer_process(void);
```

SCP 的 pacing、重传、保活、persist 等定时器都依赖此函数。即使没有收到包，也要在调用 SCP 的线程中持续处理。Pacing 现在按队首包到期的整数 tick 预约唤醒，不再每 tick 轮询；实际处理机会仍由调用方提供。细时钟不自动保证细粒度唤醒，处理过晚可能一次释放多个包。虚拟测试逐 tick 推进，不跳到下一事件时刻。

### 宏配置

超时、窗口和内存限制见 [scp.h](../../scp.h)。只有带 `#ifndef` 的宏支持直接用编译参数覆盖；核心与接入代码必须使用一致配置。AIMD 的 CA 保留 `(MSS * acked + cwnd_cnt) / cwnd` 的余数，在初始化、丢包和超时时清零；逐 ACK 丢弃余数是历史算法，不是当前行为。



## 多线程注意

使用单一执行线程，或通过同一把外部锁串行化所有调用，包括定时器处理。仅加锁不能解决回调重入。可运行的接入示例在 `test/common/udp_runner.c` 和 `test/virtual/vnet.c`；构建、诊断、失败复现和产物下载见[中文测试指南](测试说明.md)。报告应附源码版本、时钟刻度、控制器和网络条件。
