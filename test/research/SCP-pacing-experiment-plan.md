# SCP 慢启动 pacing 参数扫描计划

日期：2026-10-12。状态：已获批准；按最新要求缩短为 GitHub Actions 执行的 3 次重复扫描。

本次只研究：① pacing 参数 g 对 cwnd 演化的影响；② g 对每个固定 RTT 内 DATA 发送分散程度的影响。实验代码、采集和大规模扫描作为本次研究材料保留在独立版本中；常驻测试仍是功能测试。此次不加入 RTO 扫描，也不把之前讨论的 RTO 问题顺手修改。

## 1. 实验矩阵

| 项目 | 统一设置 |
|---|---|
| 传输量 | **1 GiB = 1,073,741,824 字节**，按二进制记录 |
| 链路 | 双向各 1000 Mbps；速率单位保持网络惯例，1000 Mbps = 10⁹ bit/s |
| 固定基础 RTT | **100 ms**，两个方向各 50 ms 延迟 |
| 配置丢包率 | 0%，记录实际 drop 计数并要求为 0 |
| 流量 | 单条正向大文件 DATA 流，反向 ACK 和校验反馈 |
| 主扫描 | g = 0.10、0.11、…、4.00，共 391 个 |
| 大 g 参照 | g = 8、16、32，共 3 个 |
| 重复 | 每个 g 3 次，新进程、新连接；共 **394 × 3 = 1182 次** |
| 环境 | 当前共享传输测试中的虚拟网络后端，seed 固定为 1 |
| 模式 | 实验版本：每次新 ACK 都使用慢启动增长规则 |

以整数 `g_hundredths` 枚举参数，避免浮点循环漏掉或重复端点。主分析组只有这一套环境；不追加其它数据量、丢包率或 RTT。

零配置丢包不等于零重传：计时器、反馈和排队仍可能触发重传，必须实测并分类。相同虚拟环境的 3 次重复主要验证可重复性，不作为 3 个独立随机网络样本，也不据此包装随机网络的置信区间。批次按重复编号轮转全部 g，减少机器状态随时间变化与 g 顺序的重合。

本地 Windows 预检已经完成，但用户要求改由 GitHub 执行；本地扫描已停止，数据独立保留，不混入 Linux 正式结果。

之前的 Linux namespace/netem 测试沿用 `setup_scp_netns.sh` 的拓扑和共享 UDP 传输程序：通过内核排队、延迟、丢包等配置施加网络条件，适合检验协议在真实 socket、内核调度和队列中的行为。虚拟网络使用同一传输逻辑，但由测试后端模拟链路序列化、延迟和投递时钟，便于重复和细粒度记录。两者各有意义；不能把相同的“100 ms、0%”标签直接视为等价观测。

虚拟时钟分辨率为 1 ms，链路投递和协议定时器有固定执行顺序；链路序列化会继续影响反馈。记录该调度顺序、代码版本和配置。实际 SRTT 可因排队变大，100 ms 只是基础 RTT，主图横轴不随 SRTT 改动。

## 3. 临时源码改动范围

在独立实验 checkout 中修改，正常分支保留基线 `3f5b10923a0854f23678a5d7da427fb6aecc9052`。

1. 在 ACK 更新 cwnd 的位置，实验版本统一执行 `cwnd + newly_acked_bytes`，保留 MSS 下限及实验 cwnd 上限。原拥塞避免增长分支在该实验版本中去掉；ssthresh 可继续记录，但不选择 ACK 增长公式。丢包时的收缩、重传与恢复逻辑保留，使实际结果仍能反映这些事件。
2. g 从本次测试程序的运行参数传入实验核心，启动连接前设置，不引入生产接口。发送间隔沿用现有 `payload × RTT / (g × cwnd)` 公式和 RTT 选择方式；不为扫描顺手改计时精度、取整或 pacing 算法。对 g=1 校验与原间隔计算一致。
3. `CWND_WIN_MAX` 临时设为 64 MiB；`SCP_RECV_LIMIT`、`SEND_WIN_INIT`、`RECV_WIN_INIT` 临时设为 128 MiB；共享传输程序的应用提交 backlog 从 1 MiB 放宽到 128 MiB。已有 1 GiB 发送/接收内存上限维持。记录实际 flight、snd_wnd、rcv_wnd、backlog 和 cwnd 是否触顶，不能把窗口限制导致的曲线重合解释成 g 无效。
4. 修改实验日志采样：从首个 DATA 开始前 5 秒每 1 ms 采样，之后每 100 ms；所有 g 和重复保持相同规则。保留初始状态与结束状态。状态日志的采样相位是现有 timer/state dump 执行位置，不能声称它代表该 tick 中所有后续 ACK 处理完的状态。
5. 在正向 DATA 的 transport-send 回调位置添加在线统计，发生在虚拟链路序列化之前。不对整个 1 GiB 保存逐包 JSON。每 RTT 聚合计数、字节、首末包和 100 个毫秒槽即可。测试程序关闭或超时时也刷新最后状态和聚合记录。

以上是实验版的完整改动边界。源码接入时保持项目代码风格，避免额外 const、嵌套三目以及无关重构。累计字节和直方图平方计算要防溢出；这属于统计准确性要求。

## 4. 统一时间轴与观察终点

取首个正向 DATA 调用发送回调的时间为 `t0`。第 k 格为：

`[t0 + k × 100 ms, t0 + (k+1) × 100 ms)`。

恰好位于右边界的数据包进入下一格。首包和末包均按回调发生顺序记录，不按序号排序；记录时间戳以及字节序号。控制包和反向 ACK 不进入主 DATA 统计。

成功运行的主观察终点为发送端确认整个 1 GiB 已被 ACK 的时间 `data_acked_ms`。另存接收完成时间、最后 DATA 发送时间和连接关闭结果，避免关闭尾巴改变主图。失败运行记录最后可观测时间和原因，保留失败前缀，不悄悄删除失败 g。

固定 100 ms 分格方便跨 g 比较，但不是测得的 ACK 往返周期。原始状态日志保留 SRTT 等字段用于辅助解释。

## 6. 每 RTT 的包分散度

每格分三种 scope：`all`、`new`、`retrans`，逐毫秒计数；要求 `all = new + retrans`，包数和载荷字节都核对。重传按连接相对字节序号及已发送范围判定，不能仅依靠一个标志位。对于混合覆盖旧/新范围的 DATA，需要明确分类规则并核查；当前顺序分片应通过首次发送范围验证。

| 指标 | 定义及用途 |
|---|---|
| 首/末包 | 每格第一个和最后一个回调的时间、字节序号 |
| 包数 N / 载荷字节 | 区分“发得少”与“相同包数分得更开” |
| 跨度 | `last − first`，同时报告 `span / 100 ms` |
| 活跃毫秒 K | 非空槽数，以及 `K / 100` |
| 最大突发比例 | `max(槽包数) / N`；越大表示单毫秒集中程度越高 |
| 集中度 HHI | `Σ(槽包数²) / N²`；全部挤在一个槽时为 1 |
| 有效活跃毫秒 | `1 / HHI`；相同包数下比较有效分散范围 |
| 包间隔均值 | `(last − first) / (N − 1)` |
| 包间隔 CV | 毫秒精度下相邻回调间隔的总体标准差 / 均值；同毫秒的间隔计为 0 |
| 零间隔比例 | `(N − K) / (N − 1)` |
| 头尾空闲 | 左边界到首包、末包到观察右边界的时长 |

不能单靠跨度判断均匀：两团突发也可能覆盖整个 RTT。主分析同时看跨度、最大突发比例、HHI 和包数。HHI 的下界随包数变化，解读时必须结合 N，不能跨不同包数直接宣称均匀性高低。

N=0 的分散指标为空；N=1 标记不可用于分散比较；全部同毫秒时平均间隔为 0，CV 未定义，不能写成 0 并解读为理想均匀。最后不足 100 ms 的格保留 `exposure_ms` 和原始统计，但不混入完整 RTT 的分散度中位数热图。整个采集精度为 1 ms，不伪造微秒级发送精度。

交付 `packet_dispersion_by_rtt.csv`（逐运行）、`packet_dispersion_summary.csv`（逐 g/RTT/scope 的重复中位数及支持数），以及 `packet_dispersion_all_g.png`。图包含全部 g 的跨度、最大突发比例和 HHI 三个热图，未定义格留白；大 g 行按类别顺序排列，不假装参数间距相同。

**观测解释：这里是协议向 transport 释放 DATA 的分散程度，不是物理网线上的间隔。** 千兆链路序列化会进一步平滑数据包；把序列化后的发送曲线作为主指标会掩盖 pacing 本身的突发。

## 7. 输入结构与脚本使用

本次已交付汇总脚本 `analyze_pacing_research.py`，依赖 numpy、matplotlib。协议采集端和 GitHub 分片运行器已经接入；旧状态日志不能补算没有记录过的逐包释放时刻，因此不能直接把旧数据当成本轮包分散度实验。

```text
campaign/
  experiment.json          本次统一参数清单
  runs/g0010-r01/
    config.json            本次运行参数、来源和文件名
    summary.json           结果及时间锚点
    state.jsonl.gz         原始状态日志（也支持未压缩）
    packet_rtt.csv.gz       在线聚合记录（也支持未压缩）
  ...
```

将随计划提供的 `SCP-pacing-experiment.json` 作为 campaign 中的 `experiment.json`。每次 config 至少含 `case_id, g_hundredths, repeat, rtt_ms, rate_mbps, bytes, loss_ppm, backend, mode, seed, stream_fd, state_log, packet_rtt_file`；另存核心 commit、二进制 SHA256、构建选项及窗口参数。state 使用原日志 `type=ss, stream_fd, t, cwnd` 字段，时间戳与采集器共用时钟。

summary 至少含 `status, first_data_tx_ms, data_acked_ms, last_observed_ms, received_bytes, checksum_ok, dropped`；记录 `receiver_payload_complete_ms`、关闭类型和失败原因。状态枚举为 `complete, failed, sim_timeout, wall_timeout, infra_error`。只有字节数及校验通过才可写 complete；停止或丢失 summary 不视为成功。

packet CSV 每格包括 all/new/retrans 三行，空格也保留，列为：

```text
rtt_index,scope,packet_count,payload_bytes,first_tx_ms,last_tx_ms,first_seq,last_seq,slot_counts
```

`slot_counts` 为 CSV 正确引号转义的 JSON 数组，长度 100；空格的首末时间、序号为空。其它时间均为与状态日志相同的绝对虚拟毫秒。

```powershell
python -m pip install numpy matplotlib
python analyze_pacing_research.py C:/path/to/campaign --out C:/path/to/analysis
# 仅中断后的明确部分报告使用：
python analyze_pacing_research.py C:/path/to/campaign --out C:/path/to/partial --allow-incomplete
```

脚本检查混合条件、重复配置、缺失配置、校验矛盾、倒退时间、缺格、计数不一致和越界包。`case_audit.csv` 与 `analysis_audit.json` 留下运行状态和统计限制。它是汇总器，不负责启动实验。

## 8. GitHub 执行顺序、时长和恢复

1. 正常基线 `3f5b10923a0854f23678a5d7da427fb6aecc9052` 在独立 CI job 编译并执行 12 项 CTest。正常分支不包含实验改动。
2. 实验分支编译一次，g=0.10、1、2、4、32 各两次预检。验证 1 GiB 校验、零 drop、窗口、逐 RTT 采集及原始绘图，并固定二进制 SHA256、源码 commit 和参数清单。
3. **16 个分片同时运行**，每片 73 或 74 次，每片至多两个传输进程，原始绘图限为一个进程。按照运行索引模 16 分配 `(g, repeat)`；预检的 10 次仅由拥有该配置的分片复用，不重复计入正式矩阵。
4. g 仍为 0.10–4.00、步长 0.01，另加 8、16、32；重复从 10 次减少到 **3 次**，正式矩阵从 3940 缩减为 **1182 次**。目标约 **30–45 分钟**，GitHub 排队和托管机器速度会影响实际时间。分片任务设 35 分钟上限；超时保留已有数据，最终报告明确为部分结果，不发布完成 tag。
5. stdout 流式写盘；每次运行保留配置、summary、独立原始曲线及压缩日志。原始日志压缩后逐字节校验 SHA256，再释放未压缩副本。不会为每次保存一个 1 GiB 文件。
6. 每片上传 full artifact（原始曲线和记录）与 compact inputs artifact（统一分析所需状态和包统计）。**汇总任务只下载 compact inputs**，避免重新聚集数 GB 的每次图片。上传使用 tar 保留目录及二进制权限；失败或超时也上传诊断，重跑 attempt 单独保留。
7. 汇总核对分片归属、重复/缺失配置、统一源码和二进制、压缩日志 SHA256，再生成所有 394 个 g 的 cwnd 表格及同图曲线、逐 RTT 首末包和分散度统计。失败前缀不悄悄删除；缺失数据只允许显式部分报告。
8. 扫描完成后，独立 checkout 正常基线，再编译并运行功能测试。实验始终位于研究分支，正常分支没有临时参数，因此无需破坏性回退。
9. 完整矩阵与功能测试通过后创建并 push `research-slowstart-g-100ms-20261012` tag，说明中包含实验 commit、GitHub run/data artifacts 链接及数据索引 SHA256。源码、脚本、配置作为一件事情提交；日志不进入 Git。

本地预检的压缩日志和独立图片约 3.0–3.2 MB/次，1182 次预计约 **3.5–4 GiB**，compact 输入明显更小；Linux 运行时继续实测。每片独立磁盘，保留至少 10 GiB 空闲，容量不足停止并保存结果，不删原始记录。GitHub artifact 保留 **14 天**，tag 永久记录版本但不延长 artifact 寿命，需要长期研究时及时下载数据。

正常网络扫参工作流在研究分支的 push 上不启动，避免把实验魔改误当作常驻功能测试，或额外启动旧的大矩阵。推送研究分支自动启动专用 `SCP slow-start pacing g research` 工作流，不改正常分支。
